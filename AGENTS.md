## Project rules

- Lesson prose, quizzes, and synthetic fixtures live in `src/content/`; components in `src/components/learn/` only render them — keeps content revisable without touching UI.
- Lab logic is pure and deterministic in `src/lib/` with tests in `src/test/` — demonstrations must be reproducible, no model calls.
- The site is static and read-only: no notes, quiz answers, or stored visitor input; lab controls are aria-pressed toggle buttons. The owner explicitly permits a session-only exploration meter: count distinct stage outputs and final concept examples actually viewed, reset on every fresh lab load, and never persist it. Use thinking points instead of input-taking.
- Cross-lesson pages (/architecture, /roadmap, /writing) are separate routes fed from `src/content/`; lesson prev/next comes from the shared `LessonPager` in the lesson route — keeps navigation consistent as lessons change.
- The home route `/` explains the RAG system itself: documents → chunks → vectors → index, then question → retrieval → context → generator → verification → release. Use an accessible HTML reader beside the state-driven 3D scene, with a static fallback, responsive flow, and reduced-motion support. Apollo is example data, not the visual subject. Do not restore decorative orbital animation. The lesson overview lives at `/overview`.
- The lab runs on the step-wise pure engine (`advance` in `src/lib/apollo-engine.ts`) over `src/content/apollo.ts`; diagram, inspector, and trace render from execution state. Generation and support judging use reviewed fixtures and must be labelled simulated. Source-backed records distinguish excerpts/paraphrases, retain real URLs/locators, and label synthetic test records by `kind`.
- Offer two independent home-lab streams: Build knowledge and Answer a question. Both are available immediately; answering uses the prepared fixture index. Use a visible, natively scrollable card gallery on the right (below the scene on narrow screens), with an introductory instruction card, a scrollbar, and smaller tilted neighbouring cards. The larger centred card selects the scene: input → individual operations → output. `src/lib/rag-gallery.ts` maps card positions to story moments, while `src/lib/rag-scroll-story.ts` supplies exact snapshots; no Next/Play click is required. Preserve the focused card and reading position when the column resizes. Reduced motion removes card tilt and depth. Retain each stream's position and exact engine snapshots for review. Hold inputs and outputs over reading intervals, and project the active input/work/output label onto the same curved path as its data packet. Precomputing a replay must not count stages as explored or rerun requests on reverse scroll. Keep all flow paths and arrowheads visible in every stage, but dim inactive routes and entities. Use the semantic route colours/key, distinct outward/return lanes, and exterior object ports shared by strokes, packets, labels, and camera bounds. Fit the active operation into the space beside/above the reader; use an overview for the complete map. Prevent projected label collisions and keep annotations clear of navigation and cards. Reserve line glow for the connection currently carrying data, and clear it at input/output or when the step is skipped/blocked. Avoid broad bloom and screen blur that wash out entities or obscure the route map. The visual world fills the viewport behind readable floating cards. Use eased perspective-camera framing, persistent, clearly visible paths and arrowheads, restrained lighting, object transformations, a holographic passage index, and a semi-hollow neural AI entity. Ambient motion must pause with the motion control, reduced-motion preference, hidden page, and open details drawer. Intentional scrolling still changes the story; paused/reduced-motion camera framing snaps to the selected step. It must never advance the engine or imply access to hidden model reasoning. Keep the explanation and output readable in the same frame.
- Make focused incremental commits with descriptive messages as work becomes reviewable. Preserve published history.
- A request story must follow one question to its checked answer or safe stopping notice. Keep the current question visible. Examples in `src/content/rag-scenarios.ts` start isolated runs; only explicit warm examples may seed their configured cache types. Routing selects a future generator but must never animate a model call before retrieval/context. The automatic large/small rule is illustrative, not a benchmark or trained classifier. Filter genuinely skipped stages from the reader, explain why no optional tool is used, and return blocked notices to the same user without releasing factual content. Preserve the all-example handoff-continuity regression test. Tool examples use one validated application-controlled read of a known passage ID supplied in the question; do not imply an autonomous agent or an LLM-selected tool call.
- Keep the five named learning views immediately discoverable alongside the two independent streams. Learning examples use isolated deterministic runs and must not mutate the active request or its caches. Closing a learning view restores its stream's exact position. Offline evaluations observe completed runs and never become a live request operation. Show prompt-prefix reuse alongside the new generation it still requires; distinguish it from an approved-answer bypass. The owner permits session-only concept exploration: count a concept only when its final result/takeaway card is viewed, never on opening or precomputation, deduplicate, reset on a fresh load, and make no mastery claim. Retain a separate viewed-stage count. Long learning cards must open at their headings and remain natively scrollable.

- Caching and Evals use dedicated 3D teaching worlds from recorded `rag-theatre` scene states, rather than relabelling the request graph. Keep cold prefill, warm prefix reuse with new generation, and the application answer-cache bypass visually distinct. Evaluation case IDs must follow their own complete paths; an expected evidence gap can pass while an answerable retrieval miss fails. Judge views show source/claim inputs and separate rubric verdicts. Slow looped visual replays must not execute requests, alter caches, increment receipts, or change card focus. Freeze their shared visual clock on pause/reduced motion/hidden page/drawer, with equivalent per-mode static fallbacks. Keep results in the same frame and move extended caveats into expandable details. Exclude Three.js scene modules from TanStack DOM source-tag injection in the existing Vite compatibility hook.

- Keep learning text readable: 16px card prose, clear semibold headings, 12px minimum metadata/custom lab labels, and sufficient contrast for secondary text. Use the shared IBM Plex Sans UI scale and `src/styles/readability.css`; simplify responsive controls before shrinking their text.

- Keep the question diagram on its aligned request spine and compact, paired service corridors. Round bends within their allocated bounds; do not fit another free spline through the shared route samples. Stroke, arrows, data packets, annotations, static SVG, and camera bounds must agree. Keep arrowheads a stable screen size across zoom, preserve the depth of 3D entities, and retain route-clearance/bounded-corner tests when changing positions.

- Keep reading-time CPU quiet: use finite demand-rendered transitions, Balanced graphics by default, and one-shot recorded concept illustrations with replay. Do not restore perpetual per-frame invalidation or camera drift. Cache route samplers; skip hidden packet work. Measure HTML labels on size/content changes and project them with transforms, without per-frame layout reads. Preserve the Input → Change → Result cues, tall-card heading entry, independent stream positions, and render-budget regression tests. Record browser measurements with the viewport and foreground state; do not present unit tests or idle readings as GPU/active-animation benchmarks.
