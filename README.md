# AI Engineering, Made Practical

Build an interactive educational website using the attached Markdown file as

the full product brief. Its title is "AI Engineering, Made Practical".

The main subject is five AI engineering concepts. My design-phase RAG project,

EvidenceLens, supplies the case study. Do not build the EvidenceLens practitioner

application itself.

For this first increment, implement:

1. The responsive learning shell, visual system, and navigation for five lessons.

2. The overview page with a concise EvidenceLens context drawer.

3. Lesson One in full: explanations, the synthetic retrieval lab, evidence

   inspector, code example, EvidenceLens application, trade-offs, quiz, and notes.

4. Browser-local persistence for notes and lesson completion.

Use the detailed Lesson One and shared lesson requirements in the attached brief.

Show the other four lessons as planned next steps until they are implemented;

do not mark them complete or fill them with generic placeholder claims.

Use deterministic synthetic fixtures. Do not enable a backend, Supabase,

authentication, paid APIs, or real model calls. All EvidenceLens application

capabilities must be labelled planned. Never invent benchmark results.

Create working code and a usable preview, not only a plan. Make reasonable

reversible UI choices. After building, verify the first increment and report

what works and what remains for the next increments.
